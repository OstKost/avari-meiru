# Mieru Client — инструкции агентам

## Цель и источники
- Рабочий MVP: macOS/Windows на Tauri v2 + Rust, Android на Kotlin + Compose, ядро `enfein/mbox`. iOS вне MVP.
- `PLAN.md` — исходный замысел; согласованные уточнения и порядок реализации находятся в `TASKS.md` и этом файле. При расхождении применять уточнения.
- Desktop использует готовый TUN ядра mbox. Rust управляет процессом, привилегиями, конфигурацией и состоянием. Собственный Wintun/utun + tun2proxy не реализовывать без пересмотра решения координатором.
- На старте реализации проект содержит только документы; команды сборки ниже становятся применимыми по мере создания соответствующих проектов.
- Активный этап: Android и Linux MVP (Ubuntu 24.04 LTS, Debian 13, актуальный Arch Linux; Linux x86_64). Рабочий macOS MVP сохранять. Android: Kotlin/Compose, API 26+, arm64-v8a и x86_64. Windows остаётся отложенным.

## Оркестрация и лимиты
- Координатор ведёт общие документы, зависимости Orca и интеграцию. Пользователь разрешил довести Android и Linux до рабочего результата через Orca workers. Старые macOS-only ограничения T0/T1 относятся к завершённому этапу. Доступность временного VPS перепроверять перед сетевой приёмкой; отсутствие сервера не блокирует локальную разработку.
- Использовать навык `orchestration` и версионный guide выбранного Orca CLI. Не заменять Antigravity/Grok внутренними subagents Codex.
- Основные задачи: Grok и Antigravity с текущими настройками провайдера. Небольшие задачи: Codex `gpt-6-luna`, effort `low`.
- Для Codex после проверки доступности использовать `--model gpt-6-luna --effort low`; для Antigravity/Grok не задавать модель принудительно.
- Не более трёх исполнителей одновременно; не дублировать одну задачу нескольким агентам. Не повышать модель автоматически при сбое или исчерпании лимита.
- Перед запуском проверять зависимости и перечень разрешённых файлов в задаче. В общем workspace допускаются только непересекающиеся записи.
- Не редактировать чужую область. Изменение общего контракта отправлять координатору; задачи с пересекающимися записями выполнять последовательно.
- Задание должно содержать цель, область записи, ограничения, зависимости и проверяемый результат. Использовать Task/Dispatch и `worker_done` по guide Orca.
- После запуска независимых workers завершать ход и ждать сообщений Orca; не опрашивать их циклом и не управлять ими через терминальный ввод.
- Отчёт: результат, изменённые файлы, команды и исход проверки, блокеры. Координатор не повторяет проверки без пробела или противоречия в отчёте.

## Архитектура и реализация
- `core/`: закреплённая ревизия mbox, сборка sidecar и Android AAR, описание артефактов. Не использовать плавающий latest.
- `configs/`: общий профиль и примеры; `desktop/`: Tauri и UI; `android/`: Compose и VpnService.
- Сначала подтвердить реальные API libbox, поддержку TUN и механизм привилегий; не писать интеграцию по предполагаемым именам из PLAN.md.
- Desktop sidecar запускается с ограниченным набором аргументов; локальный mixed proxy слушает только loopback. Не помещать пароли в аргументы процесса и логи.
- Исключить соединение с VPN-сервером из туннеля; Android использует `VpnService.protect()` через фактический API ядра.
- При отключении, ошибке и выходе останавливать принадлежащее приложению ядро и освобождать сетевые ресурсы. Проверять восстановление сети.
- Состояния UI: disconnected, connecting, connected, disconnecting, error. Запущенный процесс сам по себе не означает connected.
- Профили: сервер, порт, транспорт, имя пользователя, пароль, необязательный traffic pattern. Формат ссылок брать из upstream, не считать `mieru://` подтверждённым.
- Только фиктивные credentials в примерах. Секреты пользователя не коммитить, не выводить и не включать в отчёты.
- Минимальный UI: ручной ввод/JSON, профиль, подключение, статус и очищенные логи. QR, iOS, расширенный reconnect и оптимизация скорости отложены.

## Минимальные проверки
- Ядро: сборка для локального хоста и проверка принятия минимальной конфигурации штатной командой закреплённой версии.
- Desktop: `cargo check` в `desktop/src-tauri`, `pnpm build` в `desktop/ui`, локальный запуск Tauri после настройки проекта.
- Android: `./gradlew assembleDebug` из `android/`; установка и запуск только при наличии устройства/эмулятора.
- С рабочим серверным профилем: подключение, открытие страницы, проверка внешнего IP, отключение и восстановление сети; Desktop — также выход из трея и отсутствие оставшегося ядра.
- Нет сервера, Windows-хоста или устройства — явно отметить непроверенное. Сборка не доказывает работоспособность VPN.
- Не углубляться в тесты: без матриц совместимости, бенчмарков и полного аудита утечек. Повторять проверки только после относящихся к ним изменений.
- Подписанные установщики и релизные проверки отложены. Завершение задачи требует фактических результатов, а не предположений.
