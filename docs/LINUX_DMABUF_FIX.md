# Linux 0.1.1 — обход сбоя DMABUF

13 ноября 2026 года добавлено значение по умолчанию `WEBKIT_DISABLE_DMABUF_RENDERER=1` для Linux. Оно задаётся в начале `main()`, до Tauri/WebKitGTK и создания потоков, только если переменная отсутствует (`var_os().is_none()`). Проверки драйвера, типа сессии и дистрибутива нет. macOS-ветка запуска не изменена.

Цель — устранить сообщённый пользователем краш Arch-пакета 0.1.0 в NVIDIA/Wayland, который исчезает при ручном отключении DMABUF. Сам `Error 71` не устанавливает точную причину нарушения Wayland-протокола. В upstream описаны также проблемы explicit sync: https://bugs.webkit.org/show_bug.cgi?id=324551.

## Управление обходом

Для старого пакета:

```sh
WEBKIT_DISABLE_DMABUF_RENDERER=1 mieru
```

В 0.1.1 это значение применяется автоматически при запуске из меню и терминала. Чтобы явно разрешить DMABUF:

```sh
WEBKIT_DISABLE_DMABUF_RENDERER=0 mieru
```

Любое уже заданное значение сохраняется, включая пустое и не-UTF-8. Обход может менять производительность и особенности отображения; это настройка совместимости, а не исправление upstream-рендерера.

## Ограничения

Исходная NVIDIA/Wayland-система здесь недоступна: отсутствие краша и корректное отображение в этой среде ещё не подтверждены новым пакетом. Xvfb использует X11 и этого не доказывает. VPN-сетевые сценарии не повторялись: изменение затрагивает только раннюю настройку рендерера и версию приложения. Предыдущие результаты приведены в [LINUX_SMOKE.md](LINUX_SMOKE.md) и относятся к указанным там сборкам.
