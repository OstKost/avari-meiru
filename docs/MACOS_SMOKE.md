# Проверка первого macOS MVP

Дата: 2026-11-11. Проверка завершена на Apple Silicon с debug `Mieru.app`.

## Окружение

- Сервер: Mieru/mita v3.38.0, `31.58.213.192:28443`, TCP. Развёртывание описано в [VPS_SETUP.md](VPS_SETUP.md).
- Клиентское ядро: mbox/sing-box 1.14.3, commit `1c5b39718ebcd05e6adb31f95246fbf056be9bd7`.
- На Mac уже работал AWG VPN через `utun7`. Его не отключали, настройки не меняли.
- Тестовый профиль хранится вне проекта: `~/Library/Application Support/Mieru/vps-test-profile.json`, режим `0600`. Пароли в этом документе отсутствуют.

## Фактически проверено

1. Приложение загрузило сохранённый профиль через native IPC без возврата пароля интерфейсу. Пользователь нажал «Подключить» и подтвердил права в системном окне macOS.
2. Привилегированный supervisor запустил встроенный в `.app` sidecar. Ядро создало `utun8`, открыло mixed proxy только на `127.0.0.1:12080` и записало `sing-box started`.
3. `route -n get 1.1.1.1` показал маршрут через `utun8`. Маршрут к серверу `31.58.213.192` и исходный default оставались через `utun7`; приложение не отключало AWG. Само ядро при этом сообщало выбор физического интерфейса `en1` для исходящих соединений.
4. Обычный запрос без явного HTTP/SOCKS-прокси прошёл через TUN:

   ```sh
   curl --noproxy '*' -4 -fsS --connect-timeout 6 --max-time 12 https://icanhazip.com
   # 31.58.213.192, код 0
   curl --noproxy '*' -fsS -o /dev/null -w 'HTTPS status=%{http_code}\n' \
     --connect-timeout 6 --max-time 12 https://example.com
   # HTTPS status=200, код 0
   ```

5. Координатор нажал «Отключить» в интерфейсе. После этого UI показал «VPN отключён», `utun8` исчез, процессы root-supervisor и sing-box завершились.
6. `route -n get 1.1.1.1` и default снова указывали на AWG `utun7`. Повторные запросы вернули исходный внешний IP AWG и HTTPS `200`.
7. После действия закрытия окно стало скрытым, а процесс приложения оставался работающим. Полное завершение проверено стандартным AppleEvent `quit` — после него процессов приложения, supervisor и ядра не осталось.

В первом проходе выход проверялся только AppleEvent quit после отключения. Дополнительный проход ниже подтвердил именно пункт «Выход» из меню трея при активном TUN.

## Исправления, потребовавшиеся при проверке

- Tauri переименовывает sidecar в бандле в `sing-box`. Supervisor теперь согласованно принимает bundled и dev-имена, отклоняя чужие имена бинарников.
- `nohup` при реальном запуске через AppleScript завершался с `can't detach from console`. Фоновый запуск заменён на bash с игнорированием HUP, `exec`, перенаправлением stdin и журналов; возвращается PID supervisor.
- Непривилегированный GUI не мог читать `PROC_PIDTBSDINFO` root-процесса: macOS возвращала EPERM. Добавлены fallback sysctl/ps с нормализацией времени и handshake supervisor. Проверка executable, времени запуска и принадлежности сессии сохранена.
- После этих исправлений прошли 18 backend-тестов и повторная сборка `.app`. Сам live-тест подтвердил работоспособность запуска и остановки, не только компиляцию.

## Итог и ограничения

Подключение → HTTPS через VPS → отключение → возврат к AWG проверены. Сеть после теста работает. После заключительного прохода Mieru перезапущен и открыт в состоянии disconnected, собственное ядро не запущено. Исходного профиля Mieru не было, поэтому рабочий временный профиль оставлен в приватном `profile.json` для пользователя; отдельный `vps-test-profile.json` сохранён.

Это поверхностная проверка первого MVP. Не проверены: работа без AWG, Intel GUI, Windows/Android, DNS/IPv6-утечки, длительная стабильность, скорость и смена сетей. Аварийное завершение GUI при живом туннеле проверено в заключительном проходе ниже. Подписанный/нотарифицированный релиз не выпускался. VPS временный: после его отключения профиль перестанет работать.

## Дополнительный проход с включённым AWG

По запросу пользователя проверены настоящие пункты меню трея. Из-за custom-view в tray-icon действие AXPress на самом значке не открывает меню; реальное mouse down/up по координатам значка открывает его. Само меню после этого доступно стандартным AX-действиям. Это ограничение автоматизации не следует выдавать за неисправность меню.

- «Подключить» из трея запустил supervisor/sidecar и utun8; UI перешёл в connected.
- Однако повторный сетевой запрос в этом проходе завершился TIMEOUT (также через mixed SOCKS). Сервер продолжал работать, профиль совпадал с ранее проверенным, часы Mac/VPS совпадали. Причина пока исследуется отдельно, успешный первый проход не отменяет этот сбой.
- «Выход» непосредственно из трея при активном TUN завершил приложение, root supervisor и sidecar; utun8 исчез. AWG utun7 остался активным, исходный внешний IP и HTTPS-доступ восстановились.
- Диагностика Grok ограничена loopback-клиентом без root TUN, без изменения маршрутов и AWG. На момент этого сбойного прохода повторный TUN оставался непроверенным; в заключительном проходе ниже он повторён успешно. Работу без AWG пользователь запланировал следующим шагом.

### Уточнение диагностики повторного подключения

Grok завершил ограниченные loopback-пробы: один процесс с auto_detect=true воспроизвёл таймаут, затем три новых процесса с тем же true успешно вышли через en1; false и явный bind utun7 тоже успешны. Устойчивая причина не установлена, изменения кода/сервера/AWG не вносились. См. [RECONNECT_DIAGNOSTIC.md](RECONNECT_DIAGNOSTIC.md). После ручного подключения пользователем координатор завершил заключительный live-проход, результаты приведены ниже.

## Заключительный проход: повторное подключение и аварийная очистка

Пользователь повторно подключил приложение с включённым AWG. В этом проходе номера интерфейсов поменялись: Mieru создал `utun7`, исходный AWG работал через `utun8`. Номера `utunN` динамические; принадлежность интерфейса определялась по журналу ядра и маршрутам, а не по номеру из предыдущего теста.

1. Повторный live TUN прошёл: обычный `curl --noproxy '*'` вернул `31.58.213.192`, HTTPS example.com — `200`. GUI, root supervisor и sidecar работали одновременно. Код после диагностики таймаута не менялся.
2. После закрытия окна список видимых окон стал пустым, процесс GUI и ядро продолжали работать; HTTPS-запрос по-прежнему вернул IP VPS.
3. Реальный пункт «Показать окно» в меню трея вернул то же окно. Таким образом проверены и скрытие, и возврат окна при активном VPN.
4. Координатор проверил точный путь и UID своего GUI-процесса, затем отправил **только ему** SIGKILL. Root supervisor и sidecar сигнал извне не получали. Они самостоятельно завершились примерно за **0,41 секунды**.
5. Интерфейс Mieru `utun7` исчез. Маршрут к 1.1.1.1 и default снова указывали на исходный AWG `utun8`; внешний IP вернулся к исходному AWG, HTTPS example.com снова дал `200`.
6. Приложение перезапущено после сбоя: UI показал «VPN отключён», stale `active.json` удалён, root supervisor и sidecar не запущены. Приложение оставлено открытым для следующего теста без AWG.

Базовые проверки MVP с включённым AWG завершены: подключение, HTTPS, штатное отключение, скрытие/возврат окна, подключение из трея, выход из трея при активном TUN и аварийная очистка при падении GUI. Один ранее наблюдавшийся сетевой таймаут не объяснён и не объявляется исправленным; последующий повторный TUN прошёл успешно. Это не проверка длительной стабильности. Работа без AWG остаётся отдельным следующим этапом.
