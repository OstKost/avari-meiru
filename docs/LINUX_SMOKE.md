# Linux MVP — фактическая приёмка

Проверено 12 ноября 2026 года на macOS arm64 в изолированных Linux amd64 контейнерах Docker Desktop/Rosetta. Графическая среда — Ubuntu 24.04, Xvfb, D-Bus и WebKitGTK. GUI работает обычным пользователем; установленный helper и sidecar принадлежат root.

Это контейнерная приёмка. Настоящий рабочий стол, logind-сеанс и интерактивный диалог администратора не проверены. Для успешной авторизации использовалось временное правило polkit YES только внутри одноразового контейнера. WebKit sandbox отключался только в тестовом окружении. Конфигурация хоста и пользовательский VPN macOS не менялись.

## Сетевое ядро с внешним VPS

11 ноября до отключения VPS подтверждены Linux sidecar, loopback proxy, TUN и DNS через Mieru: HTTPS 200, внешний IP `31.58.213.192`, после SIGTERM — удаление TUN и восстановление правил/маршрутов. Подробности: [core/LINUX_SMOKE.md](../core/LINUX_SMOKE.md). Эти результаты относятся к ядру, не к графическому приложению.

## GUI, helper и локальный Mieru-сервер

Для дальнейшей интеграции использован настоящий mita 3.38.0 в отдельном контейнере той же изолированной сети с фиктивными учётными данными. Старый VPS после установленного пользователем срока не использовался. Внешний IP сервера этим локальным сценарием не подтверждается.

Полный GUI-сценарий на GUI SHA256 `2c6c56ca36ffe2bb11d27bb4c2548c7b730c667030e03615719861b317fd1c97` и helper SHA256 `15226e772787850e2bc52ab7467c1583c85db6cbb76707491b7789e212bd8f47` завершился с `FINAL_GUI_WRAPPER 0`:

- Окно «Avari Mieru» 420×720 открылось. Профиль сохранён со страницы, файл имеет режим `0600`.
- Подключение через настоящий `pkexec` и установленный helper дало UI «Подключено». Подтверждены root peer, точные аргументы helper и DNS `172.19.0.2`.
- `curl -4 https://example.com` без прокси вернул HTTP 200 через TUN.
- Отключение сняло `tun0`, очистило таблицу 2022, завершило helper и восстановило исходный DNS. Повторное подключение прошло.
- WM_DELETE скрыл окно. Команда «Показать окно» через настоящий D-BusMenu приложения вернула его в `IsViewable`. Для этого использовался тестовый StatusNotifierWatcher, а не полноценная панель рабочего стола.
- После SIGKILL точного GUI PID helper и ядро завершились, TUN/маршруты очищены, DNS восстановлен.
- GUI запущен снова, VPN подключён; команда «Выход» через D-BusMenu завершила приложение и очистила сетевые ресурсы.
- Проверенные журналы не содержали тестового пароля (`LEAK_OK`). Это не полный аудит утечек.

## Последняя сборка: фоновая проверка сервера

Последнее изменение затронуло только сохранение stdin в shell-watchdog пробника. В Ubuntu `/bin/sh` (dash) фоновый `cat <&0` немедленно получал EOF. Сохранение входа на fd 3 исправило это; fd закрывается в дочернем ядре и родителе. Относящиеся тесты watchdog/EOF cleanup прошли.

Финальные ELF:

- GUI: `1f425262582d3eba9f7aa91b38f8f52276118e68d8de5f4e2eb273840159cef7`.
- Helper: `15226e772787850e2bc52ab7467c1583c85db6cbb76707491b7789e212bd8f47` (не изменился относительно полного GUI-сценария).

Linux release build завершился с кодом 0. На этой сборке повторён только затронутый сценарий: `HEALTH_GUI_WRAPPER 0`, IPC вернул `state=ready`, «Сервер отвечает», latency 156 мс; UI показал «Готов к подключению». Проверка не открыла TUN и не изменила DNS/маршруты. После уничтожения GUI пробник отсутствовал (`HEALTH_CORE_ABSENT`), DNS совпал с исходным, `LEAK_OK`. Полный VPN-сценарий выше без необходимости не повторялся.

Манифест исходников и хеши ELF: `packaging/linux/dist/build/SOURCE-MANIFEST.txt` и `ELF-SHA256SUMS.txt`. Упаковка описана в [packaging/linux/README.md](../packaging/linux/README.md). Установка и удаление пакетов проверялись отдельно на Ubuntu 24.04, Debian 13 и Arch Linux.

## Ограничения

Не проверены интерактивная авторизация на реальном Linux desktop, Wayland, внешний IPv6, транспорт Mieru UDP, смена сетей и длительная стабильность. Подписанных релизов и публикации в AUR нет. Xvfb и тестовое polkit-правило не подтверждают пользовательский диалог авторизации.

Одноразовые GUI-контейнеры удаляются через `--rm`; тестовый локальный сервер после приёмки останавливается. Docker images и сборочные кэши сохраняются для воспроизводимой сборки.
