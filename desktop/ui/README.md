# Avari Mieru — Пользовательский интерфейс (Desktop UI)

Компактный, отзывчивый и эргономичный графический интерфейс для десктопного клиента Mieru VPN (Tauri v2 + macOS / Linux / Windows).  
Построен на базе **TypeScript**, **Vite**, **Tailwind CSS v4** и нативного API **Tauri v2** без сторонних тяжёлых UI-фреймворков.

---

## Архитектурные принципы и UI/UX решения

### 1. Название и брендинг сборки (Build-time Branding)
- Название по умолчанию: **Avari Mieru**.
- Идентификатор приложения зафиксирован (`identifier: "app.mieru.desktop"`), что гарантирует неизменность путей хранения настроек профиля и конфигураций при любом переименовании продукта.
- Поддержка кастомизации названия при сборке через скрипт `desktop/scripts/build.mjs`:
  ```bash
  # Сборка с кастомным названием приложения
  node desktop/scripts/build.mjs --name "Custom Name" --debug --bundles app

  # Или через переменную окружения
  AVARI_APP_NAME="My VPN" node desktop/scripts/build.mjs --debug --bundles app

  # Проверка сгенерированного оверлея конфигурации
  node desktop/scripts/build.mjs --name "Custom Name" --print-config
  ```
- Во frontend UI имя берется из `import.meta.env.VITE_APP_NAME || 'Avari Mieru'` и выводится в `document.title`, шапке приложения и доступных метках.
- В шапке выводится официальный логотип `/mieru-logo.png` (28×28 px, `object-contain`) рядом с названием, без сторонних брендовых меток и без привязки к конкретной ОС.

### 2. Поведение нативного окна и жизненный цикл (Window UX)
- **Размеры окна Tauri**:
  - Стартовый компактный размер: **420×720 px**.
  - Минимальные ограничения: `minWidth: 360 px`, `minHeight: 500 px`.
  - Возможность свободного изменения размера (`resizable: true`) с сохранением полной адаптивности без выпадения элементов и без поломки вёрстки.
- **Close-to-Tray (Сворачивание в трей при закрытии)**:
  - При нажатии `Cmd+W` или системной кнопки закрытия окна срабатывает `WindowEvent::CloseRequested`.
  - Вызов `api.prevent_close()` и `window.hide()` скрывает окно в область системных уведомлений (менюбар / трей), предотвращая случайное завершение сетевого туннеля.
- **Reopen из Dock / Launchpad (macOS)**:
  - Обработка `RunEvent::Reopen` в Tauri event loop: при клике на иконку приложения в Dock или повторном открытии `.app` бандла из Finder скрытое окно немедленно восстанавливается (`show()`), разворачивается из миниатюры (`unminimize()`) и получает фокус ввода (`set_focus()`).
- **Корректный выход (Quit)**:
  - При явном выходе (`Cmd+Q`, пункт «Выход» в App menu или пункт «Выход» в трее) приложение проходит через `RunEvent::Exit`, где вызывается `vpn::shutdown_for_exit(&state)` для гарантированной очистки сетевых интерфейсов ядра и остановки supervisor-процесса.

### 3. Нативное меню приложения (Native Application Menu)
Реализовано в `desktop/src-tauri/src/menu.rs` и подключено через `.menu()` в `desktop/src-tauri/src/lib.rs`:
- **App Menu (macOS)**:
  - Название подменю формируется динамически из `app.config().product_name`.
  - Пункты: «О программе», «Службы», «Скрыть» (`Cmd+H`), «Скрыть остальные» (`Cmd+Option+H`), «Показать все», «Завершить» (`Cmd+Q`).
- **Меню «Правка» (Edit)**:
  - Стандартные нативные акселераторы текстовых полей: «Отменить» (`Cmd+Z`), «Повторить» (`Cmd+Shift+Z`), «Вырезать» (`Cmd+X`), «Скопировать» (`Cmd+C`), «Вставить» (`Cmd+V`), «Выбрать всё» (`Cmd+A`).
- **Меню «Вид» (View)**:
  - Быстрый переход между экранами приложения:
    - «Подключение» (`Cmd+1` / `Ctrl+1`)
    - «Профиль» (`Cmd+2` / `Ctrl+2`)
    - «Журнал» (`Cmd+3` / `Ctrl+3`)
  - Эмиттирует семантическое событие `menu-nav` во frontend и автоматически фокусирует главное окно.
- **Меню «Профиль» (Profile)**:
  - «Сохранить профиль» (`Cmd+S` / `Ctrl+S`) — запускает валидацию и сохранение текущего черновика (событие `menu-profile-save`).
  - «Импортировать JSON...» (`Cmd+O` / `Ctrl+O`) — переключает на JSON-вкладку и открывает диалог выбора файла (событие `menu-profile-import-json`).
- **Меню «Окно» (Window)**:
  - «Убрать в Dock» (`Cmd+M`), «Изменить масштаб», «Закрыть окно» (`Cmd+W` — направляет в hide-to-tray), «Все окна на передний план».

### 4. Горячие клавиши и доступность (Frontend Accessibility)
- Во frontend (включая работу в браузере при автономной вёрстке) реализованы обработчики глобальных клавиш:
  - `Cmd/Ctrl+1`, `Cmd/Ctrl+2`, `Cmd/Ctrl+3` — переключение табов.
  - `Cmd/Ctrl+S` — сохранение профиля с блокировкой системного диалога сохранения страницы браузера.
  - `Cmd/Ctrl+O` — импорт JSON с блокировкой системного диалога открытия файла браузера.
  - `Escape` — быстрое скрытие всплывающего уведомления (toast).
  - Нативные текстовые команды (`Cmd+C`, `Cmd+V`, `Cmd+A` и др.) в полях ввода не перехватываются и работают штатно.
- Roving Tabindex навигация (`ArrowRight`/`ArrowLeft`, `Home`, `End`) сохранена для кнопок вкладок и подвкладок.

### 5. Компоновка без общего скролла (Zero Page-Level Scroll) и Height Chain
- **Цепочка высоты на всю область WebView (`html, body, #app`)**:
  - `html`, `body` и `#app` имеют явные `height: 100%`, `width: 100%`, `min-height: 0` и `overflow: hidden`, что устраняет сворачивание процентных высот в `auto` и гарантирует, что нижняя навигационная панель (`nav`) всегда плотно прилегает к нижнему краю клиентской области (y=720 при 420×720, y=500 при 360×500) на всех вкладках (`connection`, `profile`, `logs`).
  - Основной контейнер `#app-root` (`flex-1 min-h-0`) занимает всю высоту, передавая центральной секции `<main>` всё доступное пространство между фиксированным хедером (48px) и фиксированным нижним навбаром (56px).
- Сохранена эргономичная нижняя панель навигации (Bottom Tab Bar) со скользящим плавным индикатором.
- Основные экраны скомпонованы через Grid-Stack (`grid-area: 1 / 1 / 2 / 2`), скрытые секции имеют `visibility: hidden !important` и атрибут `inert`.
- Общий скролл окна отсутствует (`scrollHeight == clientHeight`, zero page-level scroll).
- Внутренний скролл включён только в области журнала (`logs-container`) и в форме профиля при экстремально компактной высоте (< 500 px).

#### 6. Процедурная 3D Canvas 2D Сфера (Procedural 3D Status Sphere)
Вместо статичных колец или тяжёлых 26MB GIF-оригиналов реализован высокопроизводительный процедурный движок на базе чистого **Canvas 2D** (`desktop/ui/src/sphere.ts`), детально воспроизводящий динамику референсов:
- **Геометрия, триангуляция и глубина**:
  - Плотная сферическая решётка Фибоначчи (1800 поверхностных вершин + 600 внутренних искр ядра) с перспективной 3D-проекцией и вращением по 3 осям.
  - Соединённая треугольная сетка (mesh lattice) для поверхностных узлов с адаптивной прозрачностью по глубине $z$, формирующая детальную высокотехнологичную кибернетическую сферу по референсу `_.gif`.
  - Прецизионные координатные HUD-дуги широты и долготы с радиальными рисками (tick marks).
  - Строго нормализованные в пространстве $[-1, 1]$ магнитные нити потока (flux filaments) с гармоническими осцилляциями ядра по референсу `Animacion.gif`, с клиппингом внутри сферы без паразитных диагональных артефактов.
  - Двухслойное свечение: яркое шумное ядро с точечным облаком и тонкий внешний ореол через предвычисленный radial glow-спрайт.
- **Двухслойная гибридная визуализация: Объёмный дымный вихрь (Smoke Vortex) + Кибернетическая Сетка (Mesh Lattice)**:
  - **Отключённые состояния (`ready`, `unconfigured`, `error`)**: полупрозрачная дымная оболочка/вихрь по референсу `_ (1).gif`. Состоит из 54 стратифицированных лент дыма (smoke ribbons) в трёх слоях глубины с многогармонической турбулентностью и 72 объёмных дымных пуфов (volumetric puffs). На верхнем и нижнем полюсах формируются выраженные световые скопления (polar luminous clusters, как в референсе), в то время как центр сферы остаётся отчётливо полым (заметная внутренняя полость без плотного яркого ядра в idle). Для максимальной производительности используется кэшированный 64×64 радиальный штамп дыма (`smokeStamp`), исключающий затратный runtime `shadowBlur`.
  - **Подключённое состояние (`connected`)**: чёткая изумрудно-бирюзовая детализированная сфера с кольцами, координатными дугами и триангуляционной сеткой (mesh lattice) по референсу `_.gif` (blur = 0px).
  - **Морфология и плавный переход (`smokeMix`)**: непрерывный кроссфейд между вихрем дыма и сеткой. При `connecting` (`smokeMix: 1.0 → 0.0`) дым собирается и кристаллизуется в чёткую структуру; при `disconnecting` (`smokeMix: 0.0 → 1.0`) сетка распадается обратно в клубящийся вихрь. Все геометрические слои (нити, сетка, дуги, частицы) плавно интерполируются через параметр `smokeMix` в едином rAF-цикле.
- **Оптический расфокус (Defocus Blur)**:
  - Мягкое CSS-размытие на Canvas снижено до деликатного диапазона **1.0–1.8 CSS px** (в `ready`/`disconnecting`/`error`: 1.4px, `unconfigured`: 1.6px, `connecting`: 0.8px, `connected`: 0.0px), что устраняет эффект «мыльного шара» и сохраняет видимость тонких струй, вихревых слоёв и полого центра. Размытие применяется через CSS `filter` canvas-элемента (совместимо с WKWebView, не зависит от DPI Retina).
- **Диспетчеризация и Reduced Motion**:
  - Строгое соблюдение `prefers-reduced-motion`: при включении режим анимации полностью останавливает цикл `requestAnimationFrame` (`animFrameId = null`, 0 FPS, без холостого rAF-цикла), отрисовывая единственный статичный перспективный кадр с немедленным применением целевых параметров состояния (`smokeMix`, цвета, blur). Поддерживается динамическое изменение через `matchMedia` change listener с гарантированной очисткой.
  - Единый планировщик рендеринга (Unified Scheduler): автоматически останавливает rAF-цикл при скрытии окна (`document.hidden`), переключении на неактивные вкладки (Профиль, Журнал) или минимизации, откладывая отрисовку до возврата на экран «Подключение».
  - Безопасный fallback: при недоступности Canvas 2D контекста UI отображает адаптивную векторную SVG-сферу с динамическим отображением смены состояний.
- **Реальная инструментация производительности**:
  - Фактический замер времени выполнения каждого кадра (`update` + `render`) с помощью `performance.now()`.
  - Скользящее окно метрик: вычисление p50, p95 и среднего времени рендера, а также подсчёт реально отрисованных кадров за секунду.
  - На Retina дисплее macOS измеренное процессорное время выполнения кадра в JS (`update` + `render`) составляет: **p50 = 2.4–2.9 мс**, **p95 = 5.2–6.8 мс**, **среднее = 2.8–3.6 мс/кадр** (замер через `performance.now()`; не учитывает отдельный GPU-композитинг окна). При Reduced Motion — 0 FPS со статичным кадром.
- **Визуальные состояния (SphereVisualState)**:
  - `cold_start`: цианово-синяя сборка сферы из рассеянных частиц (~1.4s по референсу `Animacion.gif`, статус задаётся исключительно вызывающим кодом).
  - `unconfigured`: нейтральный дымный вихрь (профиль не настроен или статус сервера неизвестен, blur = 1.2px, smokeMix = 1.0).
  - `ready`: тёплый янтарно-золотой дымный вихрь с полым ядром и светящимися полюсами (по референсу `_ (1).gif`, blur = 1.0px, smokeMix = 1.0, активируется только при подтверждённом `serverHealth.state === 'ready'`).
  - `connecting`: динамическая кристаллизация дыма в сетку и фокусировка (сине-индиговый диапазон, smokeMix = 0.35, blur = 0.8px).
  - `connected`: чёткая изумрудно-бирюзовая детализированная сфера с кольцами и триангуляционной сеткой (по референсу `_.gif`, blur = 0px, smokeMix = 0.0).
  - `error`: рубиново-красный дымный вихрь с мягким пульсирующим свечением (blur = 1.0px, smokeMix = 1.0).
  - `disconnecting`: обратный распад сетки в тёплый дымный вихрь (smokeMix = 0.75, blur = 1.0px).

### 7. Проверка доступности сервера (Server Health Check)
- Интегрирована IPC-команда `server_health_check` без аргументов (rootless HTTP GET к `example.com:80` через loopback mixed proxy `127.0.0.1` без поднятия TUN).
- Защита от race conditions:
  - Одиночный параллельный запрос (Single Flight Promise) на фронтенде с очередью новейшего запроса (`queuedHealthCheck`).
  - Состояние `busy` от бэкенда не затирает ранее полученный успешный статус `ready`.
  - Смена сохранённого профиля немедленно инвалидирует статус проверки (`serverHealth = null`).
  - Автоматический rate-limited запуск проверки при переходе в статус `connected` (если сервер ещё не проверен или результат устарел).
- Компактный бейдж статуса сервера (`#conn-health-pill`):
  - Показывает задержку ответа через сервер (`latency_ms`, время HTTP-ответа, не ICMP ping).
  - Кнопка повтора («Повторить» / «Обновить») при ошибке или готовности.
  - Подписи состояний на русском языке («Туннель активен, сервер доступен (X мс)», «Туннель активен, проверка сервера...», в браузере: «Проверка недоступна в браузере»).

### 8. Инструменты тестирования и Dev QA
- **`desktop/ui/dev-sphere.html`**: отдельная тестовая страница для разработчиков с боковым сравнением всех состояний живой сферы с исходными референсными GIF (`_.gif`, `_ (1).gif`, `Animacion.gif`), переключателями темы (Dark/Light), режима Reduced Motion и выводом реальных замеров производительности (FPS, p50, p95, ср. время кадра).
- **Безопасность Dev API**: `window.__MIERU_QA__` и `window.__MIERU_SPHERE__` доступны строго в `import.meta.env.DEV` и не компилируются в production сборку; метод `getSafeProfile()` не передаёт пароли и секреты сессии.

## Проверка и сборка

```bash
# 1. Сборка TypeScript и Vite в desktop/ui
pnpm --dir desktop/ui build

# 2. Проверка Rust-бэкенда и модуля health
cargo check --manifest-path desktop/src-tauri/Cargo.toml

# 3. Сборка приложения с кастомным названием
node desktop/scripts/build.mjs --name "Avari Mieru" --debug --bundles app
```
