# Согласованный план Mieru MVP

Дата: 2026-11-11.

Основа: [PLAN.md](PLAN.md). Подробные задания, критерии готовности и идентификаторы Orca: [TASKS.md](TASKS.md). Правила работы агентов: [AGENTS.md](AGENTS.md).

## Результат и текущий этап

Цель — рабочий MVP для macOS/Windows на Tauri v2 + Rust и Android на Kotlin + Jetpack Compose с общим ядром `enfein/mbox`. iOS вне MVP.

Этап /init выполнен: созданы AGENTS.md и TASKS.md, зарегистрирован Orca Run `run_39546fdb4578`. Пользователь разрешил реализацию первого macOS MVP. Активный путь: T0 → T1/T2 → T4 → T5 → интеграция macOS. Android и Windows отложены. T0/T1 сейчас ограничены macOS; Android API/AAR и Windows не блокируют продвижение. VPS будет предоставлен позже; без него продолжаются локальная сборка, UI и проверки жизненного цикла, а прохождение реального VPN-трафика остаётся непроверенным.

## Архитектура и оркестрация

- Desktop использует готовый TUN ядра mbox. Rust управляет процессом, привилегиями, конфигурацией и состоянием. Собственный Wintun/utun + tun2proxy на первом этапе не разрабатывается.
- Сначала подтвердить пригодность закреплённой ревизии mbox, реальные API libbox и механизм привилегий Desktop. При критическом блокере зависимые задачи остановить; архитектуру молча не заменять.
- Основные блоки отдать Grok и Antigravity с текущими настройками провайдера. Небольшие задачи — Codex `gpt-6-luna`, reasoning `low`.
- Не более трёх исполнителей одновременно, без дублирования задач. В общем workspace разрешены только непересекающиеся записи; общие документы и интеграция принадлежат координатору.
- При недоступности исполнителя фиксировать блокировку, без автоматического перехода на дорогие модели.
- Каждый отчёт содержит результат, файлы, команды и исход проверки, блокеры. Координатор повторяет проверку только при пробеле, противоречии или относящемся к ней изменении.

## Очередь реализации

1. **T0 — проверить основу и закрепить контракты. Grok.** Подтвердить сборку Desktop и Android AAR, TUN и реальные API libbox. Зафиксировать upstream commit, toolchain, механизм привилегий, исключение соединения с сервером из туннеля и очистку ресурсов. Результат — `docs/core-contract.md` с подтверждёнными интерфейсами и командами.
2. **T1 — сборка ядра. Grok; после T0.** Область `core/`: воспроизводимые сборки sidecar macOS/Windows и libbox.aar, описание артефактов и команд запуска. Подтвердить локальную сборку и принятие минимального конфига.
3. **T2 — профили и примеры. Codex Luna low; после T0.** Область `configs/`: общий профиль, схема и фиктивные примеры. Поля: сервер, порт, транспорт, пользователь, пароль, необязательный traffic pattern. Формат ссылок проверить по upstream, не полагаться на `mieru://` из исходного плана.
4. **T3 — Android MVP. Antigravity; после T1 и T2.** Область `android/`: Compose, ручной ввод и JSON-импорт, разрешение VPN, foreground service, интеграция AAR, защита сокетов, подключение и отключение. Результат — debug APK. QR отложить.
5. **T4 — Desktop backend. Grok; после T1 и T2.** Rust/Tauri: профили, sidecar, TUN ядра, привилегии и восстановление сети. Команды UI: управление профилем, подключение, отключение, получение статуса. Событие `vpn-status`: disconnected, connecting, connected, disconnecting, error. Запущенный процесс сам по себе не означает подключение.
6. **T5 — Desktop UI и трей. Codex Luna low; после T4.** TypeScript/Vite/Tailwind: профиль, кнопка, статус и очищенные от секретов логи. Закрытие окна оставляет VPN активным; выход из трея останавливает ядро и приложение. Области записи и допустимые точки подключения перечислены в TASKS.md.
7. **T6 — сборка и передача. Координатор; после T3 и T5.** Проверить совместимость результатов, устранить интеграционные ошибки, собрать доступные артефакты и документировать запуск и ограничения. Windows проверять на Windows-хосте; отсутствие среды явно отметить.

## Поверхностная проверка готовности

- Ядро: локальная сборка и проверка минимальной конфигурации штатной командой закреплённой версии.
- Desktop: `cargo check`, сборка frontend, запуск Tauri на macOS.
- Android: `./gradlew assembleDebug`, установка и запуск при наличии устройства/эмулятора.
- С рабочим серверным профилем: подключение, открытие страницы через VPN, проверка внешнего IP, отключение и восстановление доступа к сети.
- Desktop: дополнительно выход из трея и отсутствие оставшегося процесса ядра.
- Отсутствие сервера, Windows-хоста или устройства отмечать как непроверенное. Не считать сборку доказательством работающего VPN.

## Отложено

Расширенные проверки DNS/IPv6-утечек, производительности, переподключения и совместимости, QR-сканирование, подписанные установщики и релизная сертификация. Поверхностная проверка не является подтверждением отсутствия утечек. Оценка сроков из исходного PLAN.md остаётся предварительной до завершения T0.

## Уточнение параллельной реализации

После T1/T2 Antigravity готовит frontend в отдельной задаче T5-prep, параллельно backend T4 у Grok, без пересечения записей. Codex Luna low запускает окончательную T5 только после завершения обеих задач: переиспользует UI, добавляет трей и проверяет интеграцию.

## Временный сервер для проверки

Пользователь предоставил VPS `31.58.213.192` на несколько часов с SSH-доступом `root`. Отдельный Antigravity параллельно настраивает Mieru/mita и фиксирует выполненные действия в `docs/VPS_SETUP.md`; credentials сохраняются вне проекта с правами 0600. Сначала проверяется реальное loopback-проксирование, затем после исправления .app — полный macOS VPN-цикл.

## Результат первого macOS MVP

2026-11-11: debug Mieru.app собран и проверен с реальным VPS. HTTPS без явного прокси прошёл через utun8 с IP сервера; отключение завершило ядро и восстановило AWG utun7. Приложение штатно завершено, своих процессов не осталось. Фактический отчёт и непроверенные сценарии: docs/MACOS_SMOKE.md. Android/Windows и релизная упаковка остаются будущими этапами.
